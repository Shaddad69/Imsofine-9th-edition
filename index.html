Known-Route Content Views and Data-Entry Flows

Each known route mounts a fully rendered view with its own state and controls. The data-entry flows describe what is editable and where it is saved.

📋 Contestant Data Flow

  • Commander form fields: name, team, official points, rank, QR identifier & payload
  • QR display renders automatically when the QR library is loaded
  • Record appended to the in-memory roster, then persisted browser-locally
  • Gallery and Admin monitor re-render synchronously from the same source

⚖️ Judge Evaluation Saving

  • Registered-judge and assigned-contestant selectors feed one saved form
  • Scores clamped to the 1–10 rubric criteria before acceptance
  • Evaluation keyed by judge + contestant pair (strict duplicate prevention)
  • Evaluations stay separate from official points; results recompute averages on save

📈 Rank & Score Updator

  • Edits existing contestants' official points, category standings, and rank only
  • Judge Coordinator handles judge creation, editing and contestant assignments
  • Judges route lists every registered judge with live assignment status

Comprehensive audit of runtime resilience, state safety, and accessibility conventions

Unknown Routes Fallback renders Home with a gentle notice instead of a blank panel ✓ Never a white screen
Persistence Roster, judges and evaluations autosave to browser-local store; corrupt saved data caught & reset ✓ Data survives reloads
Unsaved Changes A guard warns before leaving the page mid-edit; saves confirm with an inline toast ✓ No silent data loss
Keyboard Access Launcher tiles are real buttons with visible focus rings; Enter/Space activate ✓ Full keyboard traversal
Screen Readers aria-current marks the active route; view swaps announce via a live region ✓ Route changes announced
Responsive Shell Nav collapses gracefully below 760px; grids reflow to single column; no horizontal overflow ✓ Mobile parity with desktop
